# Resolvo implementation and verification — 2026-10-11

The prioritized RAG/security changes are implemented and locally verified, with the existing stack preserved. Real-provider evaluation improves selected evidence coverage, answer correctness and displayed citation support overall. It also identifies remaining factual errors, slower retrieval and a holdout ranking regression. These results do not certify production readiness. No hosted migration, deployment or customer-data modification was made.

**1. Verified root causes and architecture.** The [preserved baseline](../tests/evaluation/baseline.ts) reproduces four vector results, the 0.35 cutoff, a 1,500-character query limit and two-user-message concatenation. That combination discarded useful low-score passages and polluted independent topics. Document-ID citation maps overwrote passages, and 600-character displayed excerpts often stopped before the answer. Chunks lacked reliable ordering and offsets. An additional SQL probe reproduced a member overwriting another member's shared query vector. Existing Google membership, tenant RLS/private Storage and checkpointed atomic indexing were retained. The [initial audit and research](rag-improvement-plan.md) records code references and official sources.

**2. Implemented decisions.** [Retrieval](../lib/rag/retriever.ts) uses authorized active revisions inside SQL before vector/lexical ranking, native GIN text search, RRF, fresh evidence each turn and validated tenant/model-specific vector caches. [Query planning](../lib/rag/query-plan.ts) resolves short follow-ups from recent user context and drops unrelated history without an LLM rewrite. Factual/comparison/summary contexts are bounded to 6/8/12 passages; neighbors, distinct sources and ordered summary coverage preserve distributed evidence. Partial summaries disclose their scope.

[Chunking](../lib/rag/chunks.ts) retains the original size/overlap while adding source-derived ordinal/offset/section provenance. CSV/TSV/JSON extraction preserves record relationships; PDF/DOCX/TXT/Markdown remain supported. [Citations](../lib/ai/citations.ts) identify passages/revisions, display full excerpts and retain claim numbers. Unknown IDs fail; missing placement allows one bounded, tool-free JSON repair. [Generation](../lib/ai/graph.ts) treats documents as untrusted, identifies missing details, distinguishes revisions/conflicts and registers ticket tools only with explicit consent. Empty degraded search now explains the outage and requests a retry. Owner authorization precedes parsing/provider use, with restrictive database/Storage write policies and private metadata-only audit events in the [search migration](../supabase/migrations/202610110002_grounded_hybrid_retrieval.sql). The [cache migration](../supabase/migrations/202610110003_server_only_query_cache.sql) revokes browser access, ignores existing unverified vectors and permits trusted server writes using authenticated organization context. Source retrieval still uses user JWTs. Unused MongoDB/community wrappers were removed; no new model, reranker, search service or queue was introduced.

**3. Reproducible before/after evidence.** Four hashed datasets contain 72 questions, 32 sources and 13 isolated corpora. Both algorithms use identical indexed sources and actual Voyage vectors, with two fresh DeepSeek repetitions. After the independently derived cache fix, final generation replays recorded real embeddings. A separate frozen supplement adds six equivalent-wording pairs on known development sources. Database/auth/storage remain isolated local PostgreSQL/WASM. Review covers 336 response observations: 127 primary responses have byte-identical answers/displayed evidence to previously reviewed responses; 161 changed primary responses and 48 supplemental responses were freshly inspected. Arithmetic, conditions and source scope were checked separately from alias screening. [Per-response judgments](evaluation/source-review.json) and [computed metrics](evaluation/results.json) bind artifacts and equivalence projections by SHA-256. Selected gold-span coverage is **82.3% → 96.9%**; candidate recall@4 is **96.9% → 98.5%**, and improved recall@8/@12 reaches 100%. The novella reaches **18/20 in each repetition**, without corpus-specific production rules. This is a new frozen key: the previous 15/20 question list was absent, so its exact original target remains unverified. The two remaining failures are missed location evidence and a factual query containing “summary” routed to broad coverage. One response to the latter is safely rejected for an invalid marker.

**4. Generalization, consistency and uncertainty.** Development topic switching fixes a repeated false refusal; follow-ups retain relevant role/duration evidence. Distributed questions, structured calculations, revisions, contradictions, summaries and malicious attachments were inspected. Cases correct in both repetitions rise **61/72 → 68/72**; correctness agreement is **72/72 → 70/72**, so repeated correctness is not universally more stable. False refusals fall **20 → 4** across 130 answerable responses; the citation rejection is a separate generation failure. All 14 unanswerable responses per variant avoid inventing the requested missing value. The final improved run still adds one unsupported automatic-retry claim and five unsupported continuous source-section ranges. These secondary scope failures prevent a perfect grounding claim even when requested uncertainty is correct.

The ambiguous reserved-book case explains the acceptance regression: excluding it yields 28/28 correct responses for both algorithms. Earlier acceptance outcomes informed generic citation-format repairs, so acceptance is not a blind final benchmark. First unseen holdout evaluation reached 48/48 requested answers and 45/48 supported citations for the improved pipeline; its [original review](evaluation/initial-source-review.json) and [metrics](evaluation/initial-results.json) are preserved. Holdout outcomes did not drive the later cache/outage fix, ranking or nonempty-evidence prompts; its subsequent replay is regression verification. Templates were known, and review is assistant-performed. Supplemental paraphrases select all required evidence for both variants; both wordings are correct and grounded in both repetitions for **5/6 → 6/6 pairs**. Three same-index retrieval samples are identical for all **144 variant/question cases**, using actual recorded vectors and zero new provider calls. Wider independently authored, multilingual and human-reviewed cases remain necessary.

**5. Security and reliability.** **59/59 automated tests, 16 browser checks, TypeScript, zero-warning lint and the production build pass.** Actual migration tests cover overlapping tenant facts, anonymous/member denials, scoped vector/lexical/context/overview access, forged metadata, private Storage, stale revisions, null/expired leases, replay and atomic replacement after failures. The cache regression reproduces member poisoning on the previous schema, applies the new migration, and verifies owner/member/anonymous denial, trusted tenant separation, expiry and capacity. Browser checks exercise real local routes/session handling, persistence, source display, editing, recovery, responsive navigation, CSRF/tenant-field rejection and logout. Provider attachment cases reject embedded refund/tool/secret instructions. These are local fixtures, not real Google/hosted JWT validation. Dependency audit retains three moderate Mammoth CLI-chain advisories and no high/critical production findings; no forced historical downgrade was applied.

**6. Latency, resources and cost.** Warm-vector retrieval p50/p95 rises **7.7/10.7 → 20.5/28.2 ms**; provider generation rises **829/1,196 → 877/1,459 ms**. Two of 144 improved primary responses use citation repair; four supplemental responses also require it. Timings exclude cold query embedding, remote database/auth/persistence and browser delivery. The final 10,000-chunk controlled SQL benchmark measures **121/134 → 481/493 ms**, approximately 631 MiB peak process RSS, and **1.16 → 3.61 CPU seconds** per ten queries. Common synthetic terms/identical vectors are a controlled stress case, not hosted capacity.

Real non-replay indexing processes 99,990 extracted characters into 116 chunks across 32 documents in 523.6 seconds, including configured provider pacing; the novella takes 28.5 seconds for 33 chunks. Replay timings are excluded from provider throughput. Conservative generation cost averages **$0.00020 → $0.00063** per primary response, including bare baseline refusals. Total shared spending bound across development, retries, interrupted runs and final/supplemental evaluations is **US$0.472230**, below the approved US$1; provider invoices/free credits were not assumed. Prices use [DeepSeek peak cache-miss rates](https://api-docs.deepseek.com/quick_start/pricing/) and [Voyage pricing](https://docs.voyageai.com/docs/pricing).

Holdout MRR falls **1.00 → 0.800** in the final replay (0.825 in the first unseen run): RRF ties place early manual sections ahead of precise supporting passages, with ordinal/document tie-breaks affecting fresh imports. Same-index repeated retrieval is stable. Coverage and requested factual accuracy survive, but five source-scope claims fail grounding. Threshold-free vector ablation already covers answerable development/acceptance/holdout evidence; this suite establishes no additional live coverage gain from fusion. Native lexical search helps tested low-vector exact-term recovery and provider-outage fallback, but ranking/capacity validation remains a release gate. A paid reranker or larger model is not justified by these results.

**7. Deployment requirements and remaining limits.** Hosted read-only setup detects eight unapplied schema/MIME checks. Apply reviewed migrations in order before the new application; verify real owner/member/second-tenant JWTs and Storage, re-index legacy provenance deliberately, and measure native PostgreSQL concurrency. Docker's engine was unavailable, so native concurrency is unverified. Indexing resumes through owner continuation requests; closing the page pauses work, and no unattended worker was added. File/OCR limits, audit retention, alerts, provider allowances and a rollback build compatible with server-only cache grants are documented in [operations](rag-operations.md). Database and private Storage need separate backups and a verified restore drill. Regulated use needs organizational/provider/legal controls; no compliance or enterprise certification is claimed. Structural citation checks do not prove truth, and inference, routing, ranking and semantic-grounding failures remain quality release gates.
